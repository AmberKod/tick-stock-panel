## 一、实时快照 + 五档盘口

端点：`GET /api/{hk|us}/deep/snapshot/{symbol}`、`/orderbook/{symbol}`

| 字段 | 说明 |
|---|---|
| `prev_close` | **上游直给的昨收**。此前当日分时的昨收要从上一会话 m1（或本地日K）反推，session key 判错就会错一整个交易日；这里一次拿到且与自己的分时同源 |
| `avg_price` / `turnover_pct` / `inside_volume` / `outside_volume` | 均价、换手率、内盘外盘 |
| `server_time` | 服务器时间戳（北京时间），<｜hy_place▁holder▁no▁813｜>的是"这份数是几点到手的"，不是取数时刻 |
| `volume_unit: "share"` | ⚠️ 这串成交量是**股数**（实证 amount/volume = 均价），而分钟K 那条线港股是**手**，两条线别混看 |

`turnover_pct` 由上游千分比换算（实测 00700 上游 0.1541 → 0.01541%，按成交量/总股本实算 0.01516%，吻合），标在 `derived` 里让前端写清口径。

**五档**：美股真五档（AAPL bid 336.67×6 / ask 336.84×6）；**港股档位恒为 0** ——
此时 `depth_available:false` + `note`，总量/内外盘仍为真数据故 `available:true`，
前端写"上游不返回"，**不画一排 0 元挂单**。九章同页盘口是 random()。

## 二、所属板块 + 同业联动

端点：`/boards/{symbol}`、`/board/{board_code}/members`、`/boardlist?kind=US_HY`

- 00700 归入 **23 个板块**、AAPL **17 个**（"港股-网络游戏" / "美股-科技巨头"…），板块自带涨跌。
- 成分股报价一次给齐：涨跌幅、**量比**、成交额、**市值**、动态/TTM PE、**股息率**、每股净资产、股本。
- 单位已交叉核对后才敢展示：总股本由上游**万股**换算成股、市值为**绝对金额**、股息率为**百分数**。
- `board_code` 必须转成协议整数码（`US0026→30026`），传字符串会静默拿到错行 —— 这层转换写在 `_to_board_code`。

## 三、港美股板块 / 概念榜

新页面 `/hkus-boards`（导航「港美股板块」）：6 类标签（US/HK × 全部/行业/概念），
每个板块给出指数涨跌与**板块内领涨股**，点行展开成分股（同源于 BoardMembersQuotes）。

## 四、多日分时 —— 只给港股，美股是"接不了"不是"没做"

上游 `TickCharts` 在港美股上的数据形状**不一样**（这是本次最值钱的发现）：

| | 港股 | 美股 |
|---|---|---|
| 块的语义 | **一天一块**（5×330 根，minutes 570~959） | **390 根一页**，不是一天 |
| minutes | 日内正常 | 跨零点累加到 1679+，mod 24 后钟点不可读 |
| 日期 ↔ 内容 | **严格对应**：day_i 收盘 == day_{i-1} 昨收（逐日验证） | **不对应**（day0 昨收 336.640 而 day1 收 340.63） |

要画美股多日分时，就得由我们给每个数据块**指定日期** —— 那是编数据，不做。
所以 `/multiday` 对港股自证通过才下发，美股 `available:false` + 明确原因。

后端还有一道**自洽守卫**：相邻交易日的「较晚那天的昨收 == 较早那天的收盘」必须成立
（容差 0.5% 吸收 float32 毛刺），一旦上游换口径或我们误读块，立刻 fail-closed，
绝不会把错日期的曲线画出来。

### vendor 改动（记在 `app/_vendor/EASY_TDX_NOTICE.txt`）

1. `MacTick` 增加 `minutes` 保留原始分钟数，`time` 改为 `(minutes//60) % 24` ——
   原本 `time(minutes//60, minutes%60)` 遇 minutes>1439 会抛 `hour must be in 0..23`。
2. `tick_charts` 的 tick 循环与尾部偏移改用 `min(total, body 长度推算)`，而不是
   `count*page_size` —— 上游这两个数不一致（5×390=1950 名义 vs total=1561 实际），
   按名义值读会越界。
