## 0. 原始需求复述

> 用户原话：「换元仿写也是可以的。目前我看了这么多国内的小说，剧情基本雷同的。
> 只需要告知用户存在风险，需要仔细查看小说内容并对比。」

拆出三层诉求：

1. **能力层面**：不要因为合规顾虑把这个能力砍掉 —— 网文是类型化创作，剧情雷同是
   行业常态，用户需要的是「借结构、不借文字」的生产力工具。
2. **风险层面**：风险必须**显式摆到用户面前**，而不是藏在免责声明里。
3. **操作层面**：用户要的是**可执行的核对动作**（"仔细查看并对比"），不是一句
   "请自行确认不侵权"。

因此本 PRD 将「风险告知 + 人工核对清单」定义为**核心交付物**，而非附加项。

## 1. 产品定位

### 1.1 一句话定位

> **换元仿写工作台 = 「抽象结构 → 原创实例化」的工作台**：只从参考作品继承
> 情绪公式（功能位、情绪节拍、信息差、反转类型等**思想层面**的抽象结构），
> 在符号、场景、关系拓扑、事件因果、桥段序列上**全部重建**，产出新作草稿，
> 并附带一份**可逐条人工核对的原创质检报告** —— 它不是洗稿机，是灵感的实例化器。

### 1.2 设计原则（4 条）

| # | 原则 | 具体含义 |
|---|---|---|
| **D1** | **只继承情绪公式，不继承任何表达** | 从范文合法继承的只有「抽象张力结构」（如"被误解→孤立→爆发达"）。具体文字、人物关系拓扑、桥段序列的特定组合、独特道具与对白，**一律不继承**。这是整个功能的法理基线，也是所有闸门的第一性依据 |
| **D2** | **风险显式化优先于风险隐形化**（★合规原则★） | 功能天然带风险，因此**把风险做成界面里最显眼、最可操作的部分**：常驻风险卡 + 生成前勾选 + ≥6 项质检对照 + 采纳前二次确认 + ack 落盘。**禁止任何形式的"静默放行"**：不静默截断输入、不静默跳过闸门、不把 unavailable 显示成 pass |
| **D3** | **人机协同 —— 仿写产物永远只是草稿** | 仿写全程**绝不直接写** `book.json` / `state.json` / `正文/`。产物落在 `rewrite/` 下，必须经用户**逐项核对 + 显式点「采纳」**才进入正式书稿。**没有一键全书入口**，一次只处理一个产物 |
| **D4** | **只提示，不保证** | 质检报告是**规则命中清单 + 人工核对项**，不是查重报告、不是法律意见。任何位置**不得出现**"保证过原创检测""保证不侵权""已通过查重"等承诺型表述；报告顶部固定声明"本报告只提示风险，不构成任何保证" |

## 2. 合规边界（核心章节）

### 2.1 法理基线（写进代码注释，作为所有闸门的依据）

- 著作权保护**表达**，不保护**思想**。类型化创作中的**功能位**（导师/对手/盟友/
  背叛者）、**情绪节拍**（压抑→误解→爆发达）、**母题**（复仇/成长/身份错位）、
  **桥段类型**（真假身份反转 / 信息差误会）属于思想层面，**不受保护**。
- 受保护的是**表达**：具体文字、**人物关系拓扑**、**桥段序列的特定组合**、
  独特道具、具体对白。
- 推论：本功能的合规与否，**不取决于"改没改人名"，而取决于 L3（关系拓扑）与
  L5（桥段序列）是否被真正重建**。这正是五层模型里 L3/L5 被定为命门的原因。

### 2.2 输入侧：接受什么 / 拒绝什么

**✅ 接受（结构笔记类，全部为抽象层信息）**

| 类别 | 举例 |
|---|---|
| 拆书笔记 / 读后笔记 | 用户自己写的、已抽象过的笔记 |
| 功能位表 | 「主角 / 导师 / 对手 / 盟友 / 背叛者 / 爱情对象」及其抽象特征 |
| 情绪节拍序列 | 「压抑 → 误解 → 孤立 → 爆发达 → 余痛」 |
| 母题与关键词 | 「身份错位」「迟到的承认」「师徒反目」 |
| 反转类型 | 「真假身份」「信息差误会」「底牌错位」 |
| 节奏参数 | 六章骨架 / 刺激点密度 / 载体轮换 |
| 原创灵感 | 用户自己的点子（可与上面各项混填） |

**❌ 拒绝（表达类）**

| 类别 | 说明 |
|---|---|
| **原文全文 / 章节正文** | 硬拒绝。理由见下方「硬裁定」 |
| 原句摘录 / 具体对白 | 拒绝作为输入；**仅允许**作为 `banned_terms` 黑名单的**比对样本**（P1，见 §4 P1-4），且不落 `blueprint.json` 正文 |
| 原作专有名词清单（作为"素材"） | 只允许作为**黑名单**（禁止出现在产物中），不允许作为"可复用词库" |
| 原作独特道具 / 功法 / 世界观具体参数 | 同上，只进黑名单 |

**硬裁定（MVP 不做，写死）**：
> **不提供「粘贴原文 → AI 自动拆出抽象结构」的入口。**
> 理由有二：① 该入口必然先把他人作品全文**落盘到 `data/`**（本项目 P1 是本地明文
> 优先，落盘即形成复制件，把合规风险从"输出侧"前移到"存储侧"）；② 该入口会让
> 用户形成"贴原文是正常用法"的认知，与 D2 直接冲突。
> 若将来要做，只允许「原文仅驻留内存、抽取完立即丢弃、绝不落盘」的旁路，且必须
> 单独立项评审 —— 本次一律不做。

### 2.2.1 原文预检闸门（本地规则，零依赖，不调 AI）

提交蓝图时对**所有自由文本字段**跑一遍本地预检。规则（自研，纯正则/统计）：

| 规则 | 判据 | 命中后果 |
|---|---|---|
| `R-len` 长度 | 单字段 > `REWRITE_INPUT_LIMIT`（默认 1200 字）且无结构化标记 | 疑似原文 |
| `R-quote` 对白密度 | 中文引号包裹的连续片段 ≥ 30 字，出现 ≥ 3 处 | 疑似对白摘录 |
| `R-para` 段落连续性 | 连续 ≥ 5 段以句号/引号结尾，且字段内无列表/表格/标题标记 | 疑似散文原文 |
| `R-exempt` 结构化豁免 | 含 ≥ 3 行 `- ` / `\|` / `#` / `key: value` 标记 | **视为笔记，直接放行**（豁免前三条） |

命中处理（**三段式，绝不静默**）：

1. **阻断**保存/生成，返回 `{ok:false, code:"rewrite_source_rejected", reason, hits:[...]}`；
2. **明示**命中了哪条规则、在哪个字段、命中位置（给出 40 字 excerpt）；
3. **引导**用户改填结构笔记，并在 UI 上给出「结构笔记应该长什么样」的示例
   （3 行示例即可，自研文案）。

诚实声明：预检是**提示性**的，不是审查结论。UI 固定一行小字：
「预检只做形态判断，不构成法律判断；是否合规由你本人核对。」

### 2.3 生成侧：五层拓扑重建作为强制闸门

| 层 | 内容 | 约束强度 | 未通过 |
|---|---|---|---|
| **L1 符号层** | 专有名词 / 地名 / 物品名 / 功法名 | **硬**（生成后可自动校验） | 产物 `blocked`，不可采纳 |
| **L2 场景层** | 标志场景 | **硬**（生成后自动校验） | 产物 `blocked`，不可采纳 |
| **L3 关系层 ★命门★** | 人物亲缘与权力拓扑 | **双闸门**：生成前强制填表 + 生成后自动校验 | 缺表 → 拒绝发起生成；校验 fail → `blocked` |
| **L4 事件层** | 因果链与冲突具体事由 | 软（生成后人工核对项） | `warn`，需人工勾选确认 |
| **L5 桥段序列层 ★命门★** | 名场面出现顺序与功能 | **双闸门**：生成前强制填表 + 生成后自动校验 | 同 L3 |

**L3 的硬要求（写进提示词 + 校验规则）**：
> 不是"换称呼"，是**整张关系图重新连线，必须换权力流向**。
> 反派从「师兄」变「表舅」不算重建 —— 那只是换词，亲缘拓扑没变；
> 从「掌门」变「物业经理」才算 —— 权力来源、可支配资源、施压方式全变了。

**L5 的硬要求**：
> 同一情绪目标必须走**完全不同的路径**。原作「当众受辱 → 隐忍 → 反击」，
> 新作不能也是这个顺序 —— 可以走「先发制人失利 → 借势 → 反被误解为背叛 → 清算」。

**可自动校验的部分（本地硬算，零依赖）**：

- **L1/L2**：产物文本 ∩ `banned_terms`（用户在蓝图里声明的原作专名/场景黑名单）
  → 命中即 fail，报告给出行号与 excerpt。（**这是最硬的一条，必须做**）
- **L3**：把蓝图里声明的「原作关系图」与「新作关系图」各自算出**拓扑指纹**
  （节点度数序列 + 关系类型多重集 + 权力流向标记），两者**完全相同** → fail；
  高度相似（度数序列一致但类型分布不同）→ warn。
- **L5**：原作桥段功能序列 vs 新作序列，算**最长公共子序列 LCS**。
  `LCS 长度 ≥ max(len) × 2/3` → fail；`≥ 1/2` → warn。
- **L4**：AI 自述因果链 + 人工核对（半自动）。

**不可自动校验的部分一律标 `unavailable` 并要求人工核对** —— 这是 D2+P2 的直接体现，
绝不允许"没样本就报 pass"。

### 2.4 输出侧：原创质检报告（8 项对照，≥6 项可人工核对）

报告 `rewrite/reports/<rewrite_id>.json`，UI 渲染为清单。每项含
`key / layer / mode / status / detail / evidence[] / human_tip`。

| # | 对照项 | 层 | 模式 | 判据（可核对） | 阻断级别 |
|---|---|---|---|---|---|
| 1 | 专名黑名单命中 | L1 | 自动 | 产物是否出现蓝图声明的原作专名/地名/物品名/功法名 | **fail = 阻断** |
| 2 | 标志场景黑名单命中 | L2 | 自动 | 产物是否出现蓝图声明的原作标志场景 | **fail = 阻断** |
| 3 | 关系拓扑指纹重合度 | L3 | 自动+人工 | 度数序列 / 关系类型多重集 / 权力流向；UI 并排展示两张关系图供肉眼比对 | **fail = 阻断** |
| 4 | 桥段功能序列重合度 | L5 | 自动+人工 | 原作序列 vs 新作序列的 LCS 占比；UI 并排展示两行序列 | **fail = 阻断** |
| 5 | 原句 / 近复制句 | L1 | 半自动 | 有摘录样本 → 12-gram 比对；**无样本 → `unavailable`，强制人工核对** | fail = 阻断 |
| 6 | 独特道具 / 具体对白命中 | L1/L2 | 半自动 | 黑名单关键字匹配；无样本 → `unavailable` | fail = 阻断 |
| 7 | **一对一人物映射**检测 | L3 | 自动+人工 | 新作角色数 == 原作角色数 且 功能位一一对应 → 提示（这是典型的"换人名不换构"） | **fail = 阻断** |
| 8 | **同构反转底牌**检测 | L5 | 自动+人工 | 反转类型 + 出现章节位置与原作一致 → 提示 | fail = 阻断 |

外加**反向校验三问**（人工项，三问各自勾选，全部"符合预期"才可采纳）：

```
 ① 遮住专有名词，还能认出是原作吗？      → 期望：不能
 ② 关系图与原作并排，是同一张图吗？      → 期望：不是
 ③ 名场面顺序连成一行，是同一条路径吗？  → 期望：不是
```

**状态语义（严格区分，禁止混淆）**：

- `pass` — 规则未命中
- `warn` — 需人工确认，勾选后方可采纳
- `fail` — **硬阻断**，不出现「采纳」按钮
- `unavailable` — **无样本 / 无法自动比对，必须由人工核对**（绝不显示为 pass）

**报告固定抬头（不可关闭、不可折叠掉）**：
> ⚠ 本报告是**规则命中清单**，不是查重报告，也不是法律意见。它**只提示风险，
> 不保证**你的作品不侵权、不保证能通过任何原创检测。最终是否可用，**由你本人
> 逐条核对后决定**。

### 2.5 风险告知：时机 × 形式 × 内容

| 时机 | 形式 | 内容 | 可否跳过 |
|---|---|---|---|
| **T1 首次进入仿写面板** | 面板顶部**常驻风险卡**（首屏展开，可折叠到一行摘要，但**永不消失**） | 3 条：① 本功能只继承抽象结构，禁止复制表达 ② 网文剧情雷同属思想层面，但关系拓扑与桥段序列属表达层面 ③ **你必须自己核对**，工具不保证 | 可折叠，**不可关闭** |
| **T2 提交生成前** | 勾选框（默认未勾选，不勾不能提交） | 「我已阅读风险：本功能不保证原创性，我将自行核对质检报告并对比原作」 | **不可跳过**（勾选值不入盘也需在请求里带 `risk_ack=true`，服务端二次校验） |
| **T3 报告展示时** | 8 项对照清单 + 反向校验三问，每项可勾选 | 每项给 `human_tip`：具体教你怎么比（例："把两行序列各读一遍，问自己是不是同一条路径"） | 未全部勾选 → 采纳按钮禁用 |
| **T4 采纳时** | 二次确认弹窗 + **落盘 ack** | 确认「我已核对，自行承担风险」→ 写入 `report.ack.{acknowledged_at, disclaimer_version}` | **不可跳过**（无 ack 记录 → 后端拒绝采纳，返回 422） |
| **T5 导出时（P1）** | 导出 md 头部可选插入风险标注行 | 记录 disclaimer 版本与核对时间 | 可配置 |

`disclaimer_version` 版本化（如 `rw-disclaimer-v1`），落盘到报告与 ack 中，
便于将来文案变更时追溯"用户当时看到的是哪一版"。

### 2.6 明确保留的禁止项清单（写进提示词 + 报告 + UI 风险卡）

**生成侧禁止（写进自研提示词的负面约束段）**：

1. ❌ 一对一人物映射（换人名不换关系拓扑）
2. ❌ 同构反转底牌（反转机制与位置照搬）
3. ❌ 复制原句 / 原作专名 / 独特道具 / 具体对白
4. ❌ 同义改写、换元不换构（洗稿）
5. ❌ 融梗（保留具体桥段组合）
6. ❌ 改人名地名后照搬情节
7. ❌ 打乱顺序后照搬
8. ❌ 一对一场景映射
9. ❌ 保留原作独有设定的具体参数（世界观规则 / 力量体系数值）

**工程侧禁止**：

10. ❌ 禁止把参考提示词包原文复制进仓库任何文件
11. ❌ 禁止把参考作品原文落盘到 `data/` 任何位置
12. ❌ 禁止在 UI 出现"保证过原创检测 / 保证不侵权 / 已通过查重"等承诺型表述
13. ❌ 禁止把 `unavailable` 渲染为 `pass`、把 `fail` 静默降级为 `warn`

## 3. 用户故事

| # | 用户故事 |
|---|---|
| **US-1** | 作为一个**有灵感的网文作者**，我想把读过的几十本书的共同结构（功能位 + 情绪节拍）记成一份结构笔记，以便把它变成可复用的创作输入，而不是每次从头想 |
| **US-2** | 作为一个**担心踩线的作者**，我想在录入笔记时被挡住"不小心贴了原文"，并且知道被挡的原因和该怎么改，以便不会因为误操作把别人的文字存进我的工作区 |
| **US-3** | 作为一个**要重建设定的作者**，我想基于结构蓝图一键生成设定卡（新符号 / 新场景 / 新关系拓扑 / 新事件骨架 / 新桥段序列），以便拿到一份**五层都已换掉**的原创骨架 |
| **US-4** | 作为一个**要写大纲的作者**，我想由设定卡生成六章级大纲（含信息增量表 / 伏笔登记表 / 刺激点分布），以便开工前就有完整的节奏骨架 |

### 5.4 ★采纳闸门（与 P3 人机协同一致性 —— 本 PRD 的硬约束）★

```
  ┌──────────── 仿写域（rewrite/）───────────┐        ┌──── 正式书稿 ────┐
  │ blueprint.json                            │        │ book.json        │
  │ drafts/<id>.md        ── 生成 ──┐         │        │ state.json       │
  │ drafts/<id>.outline.json        │         │        │ 正文/<ch>.md     │
  │ reports/<id>.json  ◀─ 质检 ─────┘         │        │                  │
  └───────────────────────────────────────────┘        └──────────────────┘
              │                                                  ▲
              │  ① 八项对照全核对 ② 反向三问全勾选                  │
              └── ③ 二次确认 → 写 ack ─── ④ POST /adopt ──────────┘
                                                    走既有入口：
                                                    write_chapter / save_outline
                                                    （带 version）/ ingest_facts
```

**规则（不可违反）**：

1. 仿写**生成**阶段（P0-4/5/6）对 `book.json` / `state.json` / `正文/` **零写入**，
   只写 `rewrite/` 下文件 —— 需有 pytest 断言（mtime + version + 文件清单三重校验）。
2. 任何产物进入正式书稿，**唯一入口是 `POST /rewrite/{id}/adopt`**，且必须：
   报告无 `fail` 项 + 所有 `warn/unavailable` 项已勾选 + 反向三问已勾选 +
   二次确认已写 ack。缺任一 → 422（错误码 `rewrite_ack_required`）。
3. 大纲采纳**必须**走既有 `save_outline` 并携带 `version`，冲突 → 409。
4. 一次采纳只处理**一个**产物；无批量采纳、无一键全书。

## 6. 约束（工程与合规）

| 约束 | 说明 |
|---|---|
| **统一 AI 通道** | 必须复用 `app/services/ai_provider.py` 的 `generate_ai_text`；**禁止另建 LLM 客户端**；`api/` 与任务层禁止直接调 `ai_provider`（AI 调用集中在 `novel_rewrite_ai.py`，与既有 `novel_ai.py` 纪律一致） |
| **零新增第三方依赖** | 后端/前端均不得新增依赖；图谱比对、LCS、n-gram 全部自研（标准库即可） |
| **仿写产物 → 采纳 → 才进正式书稿** | 见 §5.4；生成阶段对 `book.json`/`state.json`/`正文/` 零写入 |
| **诚实不可用** | AI 不可用 → `ai_unavailable`(503) + 中文 reason；输入被判原文 → `rewrite_source_rejected`(422) + hits；拓扑重建未通过 → 产物 `blocked` + 显式展示。**三者都不静默放行、不 mock、不用空列表冒充成功** |
| **只提示不保证** | 报告与 UI **禁止**出现"保证过原创检测""保证不侵权""已通过查重"；报告顶部固定声明不可关闭 |
| **状态语义不可混淆** | `unavailable` ≠ `pass`；`fail` 不可降级为 `warn`；`fail` 项存在时不得渲染可用的「采纳」按钮 |
| **许可证红线** | 见 §2.7。提示词自研 + 文件头注明「自研，未复制第三方提示词」；参考包原文不入库；轴库不进 P0 |

## 8. 待确认问题（含默认建议）

| # | 问题 | 默认建议 |
|---|---|---|
| **Q1** | 输入侧是否要开「贴原文 → AI 自动拆抽象结构」的旁路（原文仅内存、抽取后即弃、绝不落盘）？ | **默认：不做（MVP 硬拒绝原文全文）。** 理由：① 用户会形成"贴原文是正常用法"的认知，与 D2 冲突；② 即便不落盘，请求体仍会把原文送到 AI 网关，风险未消除；③ 可以让 UI 直接引导"请填结构笔记"。若确需，单独立项评审并加二次警告弹窗 |
| **Q2** | 质检报告出现 `fail` 时，是硬阻断采纳，还是允许"知情放行"？ | **默认：L1/L2/L3/L5 的 `fail` 硬阻断**（不渲染可用采纳按钮）；`warn` / `unavailable` 允许在**逐项勾选**后放行，并把勾选结果随 ack 落盘。理由：命门层（L3/L5）放行会让整个功能失去意义；非命门项全阻断又太僵。放行记录必须留痕 |
| **Q3** | 仿写产物是只在当前书下工作，还是支持"另存为新的一本书"？ | **默认：MVP 只在当前书下工作**（产物在 `rewrite/`，采纳进当前书的 `正文/`）。"另存为新书"放到 P1 —— 多书语义会牵动 `book.json` 创建与 big 索引，不宜在 MVP 引入 |
| **Q4** | 轴库（94 语体 / 137KB JSON 等，约 8MB）是否纳入本次？ | **默认：不纳入 P0**，也不入库。若采纳，放 `data/novel/resources/` 作可选资源、注明来源与用途，UI 作为可选下拉（不选也能跑通全链路）。理由：MVP 只需"一条链路跑通 + 报告可核对 + 风险告知到位"，轴库是锦上添花 |
| **Q5** | 风险告知是否需要每次会话强制弹窗？ | **默认：不做阻断式弹窗**，改用「面板顶部常驻风险卡（首屏展开、可折叠为一行、永不消失）+ 生成前勾选 + 采纳前二次确认 + ack 落盘」四段式。理由：弹窗会被习惯性点掉，反而削弱告知效果；常驻卡 + 分步确认的可追溯性更强，也不打断创作流 |
